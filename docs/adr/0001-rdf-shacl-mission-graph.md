# Usar RDF y SHACL para el Mission Graph

El Mission Graph necesita expresar Assertions tipadas, extensibles y append-only y validar su vista efectiva sin acoplarla a los esquemas internos de un Workflow. Usaremos RDF 1.1 con shapes SHACL 1.0 para sus contratos persistidos y JSON Schema 2020-12 para los Artifacts JSON; el dialecto solo identifica el lenguaje, no el validador concreto. Cada versión de Completion Contract y Artifact Type debe referenciar un shapes graph SHACL, un schema JSON o un validador equivalente para tipos no JSON mediante una identidad inmutable y versionada —URI, versión y hash de contenido—. Cambiar el validador crea otra versión y nunca modifica la referencia histórica. Cada `Validation Report` debe conservar esa misma identidad, junto con el hash del grafo o Artifact validado, para que un resultado histórico siga siendo reproducible. La v1 no exige triple store ni JSON-LD: conserva semántica y validación portables sin añadir esas dependencias operativas ni inventar un modelo de grafo propio.
